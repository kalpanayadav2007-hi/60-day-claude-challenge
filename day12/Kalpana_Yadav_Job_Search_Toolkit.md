| Phase | Focus | Suggested outcome |

| Week 1–2 | Responsive/mobile-first CSS (Flexbox, Grid, media queries) | Build 1 fully responsive landing page from scratch |
| Week 2–3 | One framework — Tailwind CSS (faster to show fluency) or Bootstrap | Rebuild the landing page using the framework |
| Week 3 | Browser DevTools | Practice debugging layout/CSS issues live; note this as a skill on resume |
| Week 4 | Figma-to-code | Pick a free community Figma template, implement it pixel-close in HTML/CSS |
| Ongoing | Portfolio | Push all projects to GitHub with README + live deploy link (Netlify/Vercel); add a Projects section to resume |

Completing even the first two phases would let you honestly claim "responsive, mobile-first design" and "Tailwind/Bootstrap" on your resume — closing 2 of the 3 biggest gaps against real job postings.

## SECTION 12: Interview Talking Points

**Most impressive/relevant point to lead with:**
Your ability to work independently and deliver in a fully remote setting — this directly answers the biggest unstated question in any remote contract interview: "can I trust this person without watching them?"

**Key stories to have ready:**
- *The freelance engagement:* Be ready to describe a specific instance where you had to interpret unclear client requirements and figure it out independently — even a small example shows judgment.
- *Why frontend, why now:* A short, honest story about what drew you to HTML/CSS/frontend work specifically (not "the tech industry" broadly) — recruiters can tell genuine interest from generic interest.
- *A learning story:* Something specific you taught yourself outside class (a CSS technique, a Git workflow, a small bug you solved) — this substitutes for "project experience" when you don't have shipped projects yet.

**Areas recruiters/hiring managers are likely to probe — prepare honest, confident answers:**
- "Do you have any live/deployed projects we can see?" — if the answer is currently no, have a direct, non-defensive response: e.g., "Not yet publicly deployed, but I'm actively building [X] and expect to have it live within [timeframe]." Avoid over-explaining.
- "How would you handle a design in Figma with no direct guidance on implementation?" — walk through your actual thought process (measure spacing, identify breakpoints, ask clarifying questions) even if you haven't done it yet formally.
- "Why should we hire a student/early-career developer for a contract role?" — lead with the remote-work reliability point above; it's your strongest genuine differentiator.
- "What's your experience with responsive design?" — be honest about current level, but pivot immediately to what you're doing about it (see Section 10 roadmap).
